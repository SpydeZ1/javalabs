## Назначение

REST API студии переводов: проекты переводов, исходные сегменты, переводы, замечания редактора и пользователи. Переводчик готовит перевод сегментов, редактор принимает его или возвращает с замечаниями, проект завершается, когда у каждого сегмента есть утверждённый перевод. Доступ к API защищён Spring Security.

## Сущности

- **Пользователь** `/api/users` — участник студии с ролью `TRANSLATOR`, `EDITOR` или `ADMIN` и статусом `ACTIVE` или `BLOCKED`. Имя и email уникальны, пароль хранится только в виде BCrypt-хеша и наружу не отдаётся.
- **Проект** `/api/translation-projects` — название, целевой язык, владелец, статус `DRAFT` → `IN_PROGRESS` → `COMPLETED`.
- **Исходный сегмент** `/api/source-segments` — текст и порядковый номер внутри проекта. Номер уникален в рамках проекта.
- **Перевод** `/api/translations` — текст сегмента, автор, статус `DRAFT` → `SUBMITTED` → `APPROVED` или `REJECTED`.
- **Замечание** `/api/editorial-comments` — комментарий редактора к переводу, `OPEN` или `RESOLVED`.

Связи: проект принадлежит пользователю, сегменты входят в проект, перевод ссылается на сегмент и автора, замечание — на перевод. Удаление проекта каскадно убирает сегменты, переводы и замечания. Пользователя нельзя удалить, пока на него ссылаются проекты или переводы. Поля `createdAt` и `updatedAt` выставляет сервер, время хранится в UTC.

## CRUD

Для каждой сущности: список и чтение по id (`200`), создание (`201`), PATCH (`200`), удаление (`204`). Статус проекта и перевода через PATCH не меняется.

В завершённом проекте нельзя менять сегменты и переводы. Утверждённый перевод удалить нельзя. Заблокированного пользователя нельзя назначить владельцем проекта или автором перевода (`409`).

## Операции

1. `POST /api/translation-projects/{id}/start` — запуск черновика. Нужен хотя бы один сегмент.
2. `POST /api/translations/{id}/submit` — отправка на проверку. Только черновик или отклонённый перевод, проект в работе, нет открытых замечаний.
3. `POST /api/translations/{id}/request-changes` — редактор отклоняет перевод и создаёт открытое замечание. Тело: `{ "content": "..." }`. Тот же результат даёт `POST /api/editorial-comments` для перевода на проверке: перевод становится `REJECTED`. К уже возвращённому переводу можно добавлять дополнительные замечания.
4. `POST /api/translations/{id}/approve` — утвердить перевод со статусом `SUBMITTED`, если открытых замечаний нет.
5. `POST /api/translation-projects/{id}/complete` — завершить проект в работе, если у каждого сегмента есть утверждённый перевод.

Открытое замечание закрывается `POST /api/editorial-comments/{id}/resolve`. Пока оно открыто, перевод снова на проверку не уходит и утвердить его нельзя.

Правила:
- у сегмента не более одного утверждённого перевода (проверка в сервисе и уникальный частичный индекс в БД);
- текст сегмента нельзя менять, а сам сегмент удалять, пока у него есть перевод на проверке или утверждённый;
- параллельные изменения одной записи защищены оптимистичной блокировкой (`version`), проигравший запрос получает `409`.

## Безопасность

### Аутентификация

- HTTP Basic, сессий нет: каждый запрос несёт заголовок `Authorization`.
- Пользователи хранятся в БД, пароли — через `BCryptPasswordEncoder`.
- Заблокированный пользователь (`BLOCKED`) войти не может. Ответ при этом такой же, как при неверном пароле.
- Имя пользователя: 3–64 символа, латиница, цифры, `.`, `-`, `_` (двоеточие недопустимо в Basic-аутентификации).

### Регистрация

`POST /api/auth/register` с телом `{ "username", "email", "password" }`. Новый пользователь всегда получает роль `TRANSLATOR` и статус `ACTIVE`, поля `role` и `status` в запросе игнорируются. Пароль: 8–72 байта, строчные и заглавные буквы, цифра, спецсимвол, без пробелов, не содержит имя пользователя. Занятые имя или email дают `409`.

Роли `EDITOR` и `ADMIN` выдаёт только администратор через `POST /api/users` или `PATCH /api/users/{id}`.

### CSRF

Защита включена для всех изменяющих запросов (POST, PATCH, DELETE), включая регистрацию. Токен хранится в cookie `XSRF-TOKEN`, при отправке его нужно повторить в заголовке `X-XSRF-TOKEN`.

`GET /api/auth/csrf` выставляет cookie и возвращает `{ "headerName", "parameterName", "token" }`.

### Роли и права

| Операция | TRANSLATOR | EDITOR | ADMIN |
|---|---|---|---|
| Чтение проектов, сегментов, переводов, замечаний | да | да | да |
| `GET /api/users/me`, свой профиль, правка своего имени и email | да | да | да |
| Список пользователей, создание, удаление, смена ролей и статусов | нет | нет | да |
| Создать проект | только на себя | только на себя | на любого |
| Изменить, удалить, запустить, завершить проект; сегменты проекта | владелец | владелец | да |
| Создать перевод | автор = он сам | нет | любой автор |
| Изменить, удалить, отправить на проверку перевод | автор | нет | да |
| `approve`, `request-changes`, создать, изменить, удалить замечание | нет | да | да |
| Закрыть замечание (`resolve`) | автор перевода | да | да |

### Ошибки

Тело ответа всегда `{ "status": ..., "message": ... }` без технических деталей.

- `401` — нет учётных данных или они неверны (с заголовком `WWW-Authenticate`);
- `403` — недостаточно прав или нет действительного CSRF-токена;
- `409` — нарушено бизнес-ограничение или целостность данных;
- `400`, `404`, `405`, `415` — ошибки запроса.

## Запуск

1. Скопировать `.env.example` в `.env` и заменить значения. Файл `.env` в git не попадает.
2. `docker compose up -d` — поднимает PostgreSQL, создаёт схему и пользователя приложения `translation_app` с правами только на чтение и запись данных (без DDL).
3. `mvn spring-boot:run` из каталога `main`.

Первый администратор создаётся при старте приложения из переменных `APP_ADMIN_USERNAME`, `APP_ADMIN_EMAIL`, `APP_ADMIN_PASSWORD`, если в БД ещё нет ни одного администратора. Пароль должен соответствовать требованиям надёжности, иначе приложение не запустится.

## Коллекция запросов

1. регистрация, CSRF-токен, ошибки аутентификации;
2. действия администратора: создание пользователя, блокировка и разблокировка;
3. чтение всех сущностей;
4. CRUD по каждой сущности от имени переводчика, редактора и администратора, включая отказы `403`;
5. сценарий согласования от запуска проекта до завершения, включая отказы `409`;
6. запрещённые удаления и удаление проекта.
