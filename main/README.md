# Translation Project

Учебная система управления проектами перевода: Spring Boot 3.4, Java 17, данные хранятся в памяти (`ConcurrentHashMap`), после перезапуска сбрасываются.

## Запуск

```bash
./run.sh          # или: mvn spring-boot:run
mvn test          # тесты
```

Приложение стартует на `http://localhost:8080`. При `app.seed-data=true` (по умолчанию) создаются демо-данные: 3 пользователя, 2 проекта, 3 сегмента, 3 перевода, 2 комментария. В продакшене флаг нужно выключить.

## Архитектура

- `controller` - приём запросов, валидация, маппинг DTO ↔ доменные объекты (`Mappers`), коды ответов.
- `service` - бизнес-логика, проверка ссылок, каскадное удаление; про HTTP не знает.
- `repository` - доступ к хранилищу (коллекции в памяти).

## Сущности

TranslationProject, SourceSegment, Translation, EditorialComment, User. Связи по id (`ownerId`, `projectId`, `segmentId`, `authorId`, `translationId`) проверяются при создании и обновлении.

## API

Для каждого ресурса: `GET /`, `GET /{id}`, `POST /`, `PATCH /{id}`, `DELETE /{id}`.

| Ресурс | Путь | Дополнительно |
|---|---|---|
| Проекты | `/api/translation-projects` | |
| Сегменты | `/api/source-segments` | `GET /project/{projectId}` - по порядку `order` |
| Переводы | `/api/translations` | `GET /segment/{segmentId}` |
| Комментарии | `/api/editorial-comments` | `GET /translation/{translationId}` |
| Пользователи | `/api/users` | |

## Правила

- `PATCH` меняет только переданные поля. `id`, `createdAt`, `updatedAt` клиент задать не может.
- Ошибки: 400 (невалидные данные или ссылка на несуществующую запись), 404, 409 (конфликт).
- `DELETE` всегда отвечает 204 и каскадно удаляет зависимые записи, висячих ссылок не остаётся: проект → сегменты → переводы → комментарии; пользователь → его проекты и его переводы.
- Время (`createdAt`, `updatedAt`) задаёт только сервер, значения из запроса игнорируются.
- Если статус не передан, перевод создаётся как `DRAFT`, комментарий как `OPEN`, проект как `DRAFT`.
- Пароли хранятся как BCrypt-хеш и в ответах API не отдаются.

## Ограничения

Нет аутентификации и авторизации: роли `USER`/`EDITOR`/`ADMIN` пока ни на что не влияют.
